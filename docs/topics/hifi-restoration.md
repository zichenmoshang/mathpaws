# 高保真 UI 还原工作流：AI 生图 + 语义拆层 + 坐标回贴

> **一句话摘要**：用 AI 文生图产出高保真原稿，用语义拆层服务把原稿拆成透明图层并记录每个图层的 bounding box，前端按原稿坐标把图层重新拼回——配合坐标台账与离线真值回归，把"设计稿还原"变成一条可复现、可验收的工程流水线。
>
> **适用读者**：独立开发者 / 小团队，没有专职设计与切图人力，又想在游戏里实现高保真拟物 UI（含换装类复杂资产）的开发者。

---

## 1. 为什么不是手写 SVG，也不是切图外包

儿童游戏风格的 UI 是重度拟物的：线圈笔记本、木栅栏、宝箱、缎带、搪胶质感的角色。面对这类视觉，常规路线各有硬伤：

- **手写 SVG / CSS 硬画**：拟物质感（光影、纹理、立体描边）用代码画出来成本极高，且效果天花板明显；
- **请设计 + 切图外包**：独立项目没有这个人力和预算，且迭代一次图就走一轮外包流程；
- **AI 整图直出当背景用**：整张图是一个死平面——文字改不了、按钮没状态、分辨率缩放后糊，也无法做局部动效与换装。

本项目走第四条路：**AI 负责"画"，确定性脚本负责"拆"和"贴"，前端负责"组装"**。生成模型做它擅长的（视觉质量），工程管线做它擅长的（坐标、对齐、复现、验收），各取所长。文字一律不进图层——文案由前端排版，保证可换、可缩放、可访问。

## 2. 工作流总览

```
AI 文生图高保真原稿 (design/high-fi/<page>.png)
   │
   ▼  layer_decomposition 语义拆层 (design/paperdoll-spike/decomp.js)
z0 重绘背景 + z1..zN 透明图层（名称 / 描述 / bounding_box）
   │
   ▼  逐元素验收（棋盘格 / 对比原稿 / bbox 交叉校验）
选定图层导出 WebP → apps/web/src/assets/hifi/<page>/
   │
   ▼  登记坐标台账 manifest.json（来源稿 / 画布 / 每层 bbox）
前端运行时按原稿坐标回贴重组（CSS 百分比定位）
   │
   ▼  真值回归验收（离线 PIL 回贴比对 + 运行时走查）
```

关键原则贯穿始终：**高保真原稿是唯一视觉真值（ground truth）**。拆层只是提取手段，bbox 只是坐标载体，最终渲染结果必须能回到原稿去比对——比对不上就是 bug，不是"风格差异"。

---

## 3. 拆层：layer_decomposition 的本质与边界

拆层用的是 doubao-seedream-5.0-pro 的 `layer_decomposition` 能力：输入一张图，输出 `z0` 背景 + 若干语义对象的透明 PNG，每层带名称、描述和 bounding box，并自动补全被遮挡的部分。入口脚本 `design/paperdoll-spike/decomp.js`，拆层规格全文在 `docs/design/hifi-ui-extraction-spec.md`。

要用好它，先接受三条本质属性：

1. **输出是重绘，不是原图像素**。各层的光影、描边、细节会有细微变化——适合拟物容器 / 道具（笔记本、宝箱、铅笔），不适合需要像素精确的东西（分割线、虚线框、1px 装饰、logo）。判断口诀：**这个元素重绘了用户看得出来吗？看得出来就不用**；
2. **只拆"可见且语义独立"的对象**。用 prompt 强制拆出被遮挡内容（如"帽子 / 头 / 身分三层"）会被服务确定性拒绝（HTTP 400）——所以角色换装**不走这条通道**（见 §6）；
3. **结果随机、不可复现**。同图多次调用结果不同，素材必须一次验收锁定进仓库，不进需要确定性复跑的批量管线。

调用约束（硬规则）：必须且只能 1 张输入图；`watermark: false` 必传（默认会带"AI生成"水印）；prompt 通常不传，自动语义分组效果最好。

### 三个必知几何事实

- **层 PNG 的像素尺寸 ≠ bbox 尺寸**（实测 0.9×–2.4×，模型按内容原生分辨率出图）。回贴必须 `drawImage(layer, bbox.x0, bbox.y0, bbox.w, bbox.h)` 按 bbox 缩放；
- **z0 是重绘背景，不要当原图用**；缺元素时以输入稿为准重切或手工补；
- **`absolute` 与 `normalized` 两套 bbox 可能互相矛盾**（实测某进度条层 absolute 与 normalized 换算值相差数百像素）。回贴前必须交叉校验：先把 normalized（0–1000 坐标系）换算回绝对像素与 absolute 比对，再用层 PNG 原生尺寸验证哪一套自洽；仍无法判定时以 normalized 为准，并在台账记 `bboxNote`——禁止静默采用。

## 4. 坐标台账：manifest / anchors 是管线的"数据库"

拆层产物若不登记坐标，一个月后没人知道某张 WebP 该贴在哪、从哪来。项目用两级台账解决：

**页面级 manifest**（`apps/web/src/assets/hifi/<page>/manifest.json`）记录来源稿、生成方式、原稿画布尺寸、每层的语义名与 bbox：

```json
{
  "source": "design/high-fi/quiz/quiz-page.png",
  "via": "seedream-5.0-pro layer_decomposition (watermark:false)",
  "canvas": [2364, 1773],
  "note": "蓝底未采用 z00 重绘背景，前端用 CSS 渐变近似；题目文字前端排版",
  "layers": [
    { "name": "page-left.webp", "bbox": [177, 331, 1173, 1661] }
  ]
}
```

`note` 字段同样重要：哪些层**没采用**、为什么（如重绘背景被 CSS 渐变替代以避免缩放色差）、文字是否前端重排——这些决策不记下来，下次维护就会重蹈覆辙。

**系统级 anchors**（换装系统，见 §6）：`design/paperdoll-assets/anchors.json` 是锚点参数的**单一事实源**——由导出脚本从切层常量直接生成，不手抄、不维护第二份。

台账的价值在于：运行时回贴、离线回归、资产管理三方消费同一份坐标，任何一方发现不一致都是可定位的台账问题，而不是玄学视觉偏差。

## 5. 运行时重组：按原稿坐标回贴

前端重组非常朴素：以原稿画布（如 2364×1773）为坐标系，把每层 bbox 归一化为百分比，`position: absolute` 逐层贴回。以 `apps/web/src/components/ChestPanel.tsx` 为例：

```tsx
{/* 拆层回贴（bbox 归一化为百分比，2364×1773） */}
<Layer src={chest}   bbox={[831, 411, 1567, 1041]} />
<Layer src={scroll}  bbox={SCROLL_BBOX} />
```

由于图层与 bbox 来自同一份原稿，缩放只发生在"百分比 → 容器尺寸"这一步，天然响应式、跨 DPR 清晰。烘焙在图层里的动态内容（如倒计时数字）则用 PIL 擦除后由前端排版覆盖——擦除方法见 §7。

**验收是两级回归**：

- **离线真值回归**：PIL 脚本把全部图层按 bbox 回贴成整图，与原稿并排比对，任何 bbox 疑问先看回贴结果再决定采用值；
- **运行时走查**：真机页面上核对层级、遮挡、信息密度。走查结论会回流台账——被否的图层在 manifest 里记 `unused` 同步移除，不是删文件了事。

## 6. 极致案例：纸娃娃换装系统

换装是这套方法论的极限压力测试：6 套服装 × 多顶头饰自由组合，任意搭配都必须无接缝、无遮挡错误。语义拆层在这里**明确不可用**（重绘破坏几何对齐、拒绝拆遮挡），但方法论是同一套：**原稿即真值 + 确定性管线 + 台账 + 全组合回归**。

### 架构与管线

- **槽位设计**：套装是**一整张全身图**（消除上衣/下装硬切的 1px 缝），只有帽 / 鞋两个弱耦合独立槽，z-order 为 `outfit → shoe → hat`；
- **工具边界**：AI（image_edit 带 core-ip 参考图）只负责"画"母图和补画被遮挡像素（摘帽后的头发、光脚的脚）；**抠图 / 切层 / 对齐全部走确定性脚本**（rembg 分割 + HSV 颜色分割 + Pillow）——分割模型不改动主体一个像素、可复现、可批量；
- **五步流水线**（`design/paperdoll-spike/`）：`step1` rembg 抠图 + 坐标网格 → `step2` 切 3 槽图层（帽区从戴帽源图自身分割，洞与帽同形）→ `step3` 接缝放大质检 → `step4` 导出冻结资产（anchors/manifest/WebP@2x/图标）→ `step5` 用导出的 WebP **异路径回读**重新合成验证；
- **运行时合成**（`packages/ui/src/paperdoll-compose.ts`）：v5 起改为 N+M 运行时合成——生产资产从 46 份预烘焙组合瘦身到 14 份基础图层（6 bodies + 3 heads + 2 hats + 2 masks + 1 shoe），帽挖洞、头颈缝合在运行时完成；合成在离屏 2048 画布按原生分辨率叠加后**整体一次缩放**，根除"每层独立缩小 → 边界采样 → 1px 缝"。

### 真值矩阵

验收不是"看一眼觉得行"，而是**全组合矩阵回归**：6 套装 nohat 光脚基线 + 在架头饰 × 6 套装的逐格组合（v4 定稿时为 4 顶在架头饰，wizard 帽下线前为 5 顶）+ 摘帽切换 + 穿鞋组合，每格核对无缺块 / 重影 / 白边 / 光环、颈部接缝自然、帽与眼睛对齐。预烘焙的 per-body 变体保留在 `_truth/` 目录作为回归基准，v5 运行时的 N+M 合成结果必须能逐格对回这些真值图。矩阵有一格不过，该次切层就不过。

## 7. 踩过的坑与经验（实测档案提炼）

1. **AI 拆层结果不可复现，验收即冻结**。同一张稿两次拆层结果不同，合格的层必须当场验收、导出、登记台账后进仓库；把拆层当"随时可以重跑的预处理"会反复消耗配额且对不上台账。
2. **两套 bbox 坐标系会打架，交叉校验不能省**。`absolute` 与 `normalized` 曾在个别层相差数百像素；校验顺序：normalized 换算 → 与 absolute 比对 → 用层 PNG 原生尺寸仲裁 → 仍有疑问以 normalized 为准并记 `bboxNote`。
3. **像素级元素别指望拆层**。quiz 页右页的虚线手写框在重绘中直接消失；分割线、细边框、1px 装饰一律前端 CSS/SVG 实现，不进图层。
4. **擦除烘焙内容要用统计方法，别用纯色补丁**。资源牌 / 倒计时牌上烘焙的数字，纯色补丁在渐变底上必显眼——正确做法是"逐行采样干净列带均值填充"（脚本见 `_tmp/export_farm_settings_layers.py`）；且烘焙物会越出预估边界（宠物卡片里犬猫身体伸出到 0.72W 处），擦除区要放大。
5. **热点区域不要用容器 bbox 均分**。farm 地块按外框四等分，木栅栏立柱和中栏导致内容偏移 50–70px；改用 PIL 实测内容矩形（土壤色阈值 + 行列投影）定热点。
6. **采用的层不是越多越好**。拆出的大倒计时牌、大按钮在真机走查中因"挡植物 / 信息密度过高"被否决——以页面实际信息密度为准，走查结论回流 manifest 记 `unused`。
7. **生成模型不做抠图**。扩散模型"去背景"本质是重画整图，会漂移颜色 / 边缘 / 比例，常返回白底或棋盘格假透明；抠图用分割模型（rembg / BiRefNet），补画才用生成模型。

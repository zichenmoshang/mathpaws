# 高保真稿 UI 元素提取规范（Seedream layer_decomposition）

> 版本：v1.2　|　最后更新：2026-10-06（§8/§9 案例档案合并压缩为 §8）
> 适用问题：**设计稿（高保真 PNG/JPEG）里已经画好的拟物 UI 元素，如何切成透明素材给前端用。**
> 配套实测档案：`decomp-quiz`（quiz-page 拆层全产物；ad-hoc 工作区内容按约定可随时清理，拆层产物以 `apps/web/src/assets/hifi/quiz/` 与 §8 描述为准）；入口脚本：`design/high-fi/decomp.js`。
> 与其他切图通道的分工见文末"通道选择表"；角色换装类需求不要用本文通道，见 [character-generation-spec.md](./character-generation-spec.md)。

---

## 1. 先认清它是什么：语义提取 + 重绘，不是像素切分

`layer_decomposition`（doubao-seedream-5.0-pro）把一张图理解为多个语义对象，为每个对象输出**一张透明 PNG + 名称 + 描述 + bounding_box**，并自动补全被遮挡部分。

三条本质属性决定全部使用边界：

1. **输出是重绘，不是原图像素**：z0 底图是模型重新生成的背景，各层元素光影 / 描边 / 细节会有细微变化，不可作为像素基准；
2. **只拆"可见且语义独立"的对象**，不脑补被遮挡内容以外的结构；用 prompt 强制拆出被挡住的部分（如"帽子 / 头 / 身分三层"）会被服务确定性拒绝（HTTP 400 `image content could not be processed`）；
3. **结果随机、不可复现**：同图多次调用结果不同，素材必须一次验收锁定，不进需要确定性复跑的批量管线。

## 2. 适用 / 不适用清单

| | 元素类型 | 结论 |
|---|---|---|
| ✅ | 拟物容器/道具：笔记本、宝箱、铅笔、图标摆件、卡片本体 | 重绘可接受，透明边缘干净，自动补遮挡 |
| ✅ | 完整按钮（含其文字作为图形的一部分） | 可用；但若文案会变，应只用其底板或让前端重绘 |
| ⚠️ | 文字层（标题、算式、标签） | 能切出且中文零错字，**但默认不作为素材**——文字一律前端排版（可换文案 / 可缩放 / 可访问性）；只在"纯视觉装饰且永不变化"时考虑 |
| ❌ | 需要像素精确的图形：分割线、虚线框、细边框、1px 装饰 | 实测会丢细节（quiz 右页虚线手写框在重绘中消失） |
| ❌ | 品牌 logo / 标准图标 | 用 SVG / 官方资产，不接受重绘偏差 |
| ❌ | 角色抠图、换装拆层 | 走 BiRefNet 与运行时合成；本通道重绘且拒绝拆遮挡（见通道表） |
| ❌ | 要精确还原设计稿的整页复刻 | 按 bbox 回贴只是"接近"，不是 Figma 级还原 |

判断口诀：**这个元素重绘了用户看得出来吗？看得出来就不用。**

## 3. 调用约束（硬规则，源自服务校验）

- 模型固定 Pro；**必须且只能 1 张输入图**（不支持组图 / 批量）；
- 输入 png / jpeg 均可（本地图由包装脚本转 base64 data URI 内联，命令行传不了 ~300KB 参数）；
- `size: 'auto'`（默认），保留输入分辨率，实测 2364×1773 可用；
- **必须 `watermark: false`**（默认 true 会带"AI生成"水印，正式素材不可用）；
- prompt 通常**不传**（自动语义分组效果最好）；只在需要合并 / 命名引导时传，且不得要求补画遮挡；
- 每次调用消耗 1 次 Pro 配额；Key 只从环境变量 `$env:AGENT_PLAN_API_KEY` 读取，不回显不落地（仓库 secrets 规则）。
- **文生图出稿落盘被沙箱 EPERM 拦截时**（generate.js 默认保存目录在仓库外，2026-10-05 实测）：生成仍成功、资源 URL 在输出 JSON 里，用 `Invoke-WebRequest -Uri '<url>' -OutFile 'design/high-fi/<page>.png'` 直接下载进仓库即可（URL 24h 有效）；过滤 stdout 提取信息时不要把 URL 滤丢。

## 4. 输出结构与三个必知几何事实

每次返回 `z0 背景(jpeg) + z1..zN 元素层(png)`，每层字段：`z_index / name / description / size / bounding_box.absolute[x0,y0,x1,y1] / .normalized`（normalized 为 **0–1000 坐标系**）。

1. **层 PNG 的像素尺寸 ≠ bbox 尺寸**（实测 0.9×–2.4×，模型按内容原生分辨率出图）。回贴时必须：
   `drawImage(layer, bbox.x0, bbox.y0, bbox.w, bbox.h)`——按 bbox 缩放，不能按图层原始尺寸；
2. z0 是重绘背景，**不要**把它当原图用；缺元素时以输入稿为准重新切或手工补。
3. **`absolute` 与 `normalized` 两套 bbox 可能互相矛盾**（实测 splash z4 进度条：absolute x0=100，
   normalized 203/1000×2364=480，其余 6 层两套都一致，仅此层异常；误用 absolute 会导致进度条偏左
   遮挡数字）。回贴前**必须交叉校验**：
   - 先按 `normalized` 换算回绝对像素（`×输入宽/1000`、`×输入高/1000`），与 `absolute` 比对；
   - 再用**层 PNG 原生像素尺寸**验证：若某层原生宽/高与其中一套 bbox 的宽/高吻合（≈1×，通常
     该层未被额外缩放），以吻合的那套为准；
   - 仍无法判定时，以 `normalized` 为准（实测异常出在 absolute，normalized 与原生尺寸自洽），
     并在资产台账 manifest 里记录修正值与原因（`bboxNote`），禁止静默采用。
   - 离线 PIL 回贴比对（§5/§6）是兜底：任何 bbox 疑问都先回贴并排看原稿，再决定采用值。

## 5. 生产 SOP

```powershell
# 1) 输入稿放临时目录（高保真原稿只读，不修改）
# 2) 调用（Key 已在环境变量；脚本不打印 Key / URL / 长 JSON）
node design/high-fi/decomp.js `
  design/high-fi/<page>/<page>.png `
  design/high-fi/_tmp/decomp-<page>
# 产物：layer_zNN_*.png/jpg + layers.json（名称/描述/bbox/尺寸台账）
```

3. **逐元素验收**（§6 清单），不合格的层丢弃重跑或改走代码绘制；
4. 选中的层导出到正式资产目录：
   - 建议路径 `apps/web/src/assets/hifi/<page>/<element>.webp`（透明保留用 WebP alpha；需要无损边缘时 PNG）；
   - 文件名用语义名（`notebook.webp`），不用 `layer_z03`；
   - **同步在资产台账记录 bbox 与来源稿**（新建 `assets/hifi/manifest.json` 或就近文档），否则下次无人知道它的原始位置与缩放比；
5. 临时产物留在 `_tmp/`，可整体删除；`response.json` 不入库。

## 6. 验收清单（每个采用的层逐项过）

- [ ] 棋盘格背景查看：边缘干净、无白边 / 光晕 / 杂色边；
- [ ] 与输入稿同区域对比：造型一致，无多 / 缺部件、无文案错字；
- [ ] 按 bbox 回贴到原稿截图上：位置 / 尺寸对齐，缩放后无糊边；
- [ ] **absolute 与 normalized 两套 bbox 已交叉校验**（§4 第 3 条，用层原生尺寸验证），
      修正值已记 `bboxNote`；
- [ ] 无水印；
- [ ] 确认该元素"重绘可接受"（§2 口诀），文字类已确认前端不重排；
- [ ] 命名、bbox、来源稿已登记台账。

## 7. 通道选择表（项目内全部"从图里取东西"的场景）

| 场景 | 通道 | 原因 |
|---|---|---|
| 高保真稿取拟物 UI 元素 | **本规范：layer_decomposition** | 语义提取 + 自动补遮挡，省去手工像素定位 |
| 白底角色 / 道具去背 | **BiRefNet-lite（rembg 内置）** | 像素忠实、本地、零配额、可批量 |
| 角色换装 | **N+M 运行时合成**，不用任何拆图 API | 遮挡补全服务拒绝、重绘破坏 anchors 几何 |
| 精确图形 / 图标 / 文字 | **前端 SVG / CSS / 文本排版** | 要求像素精确与可维护 |
| 扭蛋卡背等精确图形 | BiRefNet + PIL trim；flood-fill 仅降级 | 重绘不可接受 |

## 8. 实测案例档案（证据区：§2–§4 的规则均出自以下实测）

- **2026-10-03 quiz-page（2364×1773 → 9 层）**：按 bbox 回贴版式与原稿几乎一致、中文零错字、笔记本装订环与遮挡纸面自动补全。问题：右页虚线手写框在重绘中消失（→ §2 像素精确类不用本通道）、默认参数带水印（→ §3 必传 `watermark:false`）、层尺寸 ≠ bbox（→ §4）。白底戴帽角色（festival-elf）对照实验：自动归为单层、prompt 强拆被 400 拒绝（→ 本通道不用于换装，§7）。
- **2026-10-05 farm / settings / pet（三稿 45 层采用 27）**：absolute↔normalized 交叉校验 maxdiff≤2、PIL 全层回贴与原稿一致（产物 `_tmp/decomp-*-v2/`）。沉淀技法：**烘焙数字擦除**用"逐行采样干净列带均值填充"（纯色补丁在渐变底必显眼），擦后数字前端排版；**烘焙形象擦除**注意烘焙物会越出预估边界（犬猫右侧身体伸出 0.72W），擦除区要放大并避开角标；**地块热点勿用容器 bbox 四等分**（立柱 / 中栏占位致偏移 50–70px），用 PIL 土壤色阈值 + 行列投影实测内容矩形；**采用层不是越多越好**——大倒计时牌 / 大"种植"按钮在真机走查被否，以页面实际信息密度为准（脚本均在 `_tmp/`）。
